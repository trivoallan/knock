# knock — Roadmap

*Format: What exists / Now / Deferred / Later. Status as of **0.9.3** (2026-08), plus what has merged
on `main` since (2026-09). The front door is built, enforceable, and publicly verifiable, and it now
takes agent skills from git as well as images from registries. What it cannot do yet is **refuse
before it places**: every *no* knock can say today — `attach --fail-on`, `audit --fail-on-unsigned`,
`verify` — lands on a digest that is already in the registry. The next heading is **admission**.
Forward direction lives in *Now / Deferred / Later* **by direction, never by version**: a version is
cut when a real increment lands, but this roadmap always shows the heading, decoupled from release
tags. What shipped, and why, lives in the [CHANGELOG](../CHANGELOG.md) and the
[ADRs](architecture/decisions/); this page keeps only the direction.*

## Product thesis

knock is a **stamper**, not a query engine. It is the single front door through which external
artifacts enter your organization — container images from registries and, since ADR 0048, agent
skills from git: the same risk, someone else's code running on your hosts, one artifact class over.
It hardens what it rebuilds (internal CAs, internal package mirrors) and stamps what it places with
**standardized, portable provenance** — plus, on every placed image, a **package-level SBOM** (SPDX
and/or CycloneDX, generated by standalone syft on copy and rebuild alike). The value lands at incident
time — when a critical CVE drops, the stamp (lineage, ownership) and the SBOM (package inventory) turn
*"which images ship the vulnerable package, and who owns them?"* into one query in the tools you
already run. knock produces the facts; it never runs the query — still a stamper, not a query engine.

Two consequences drive everything below:

1. **The label is the product.** Because knock's value flows through the stamp *and the SBOM* into
   someone else's query tool, the provenance surface (the annotation schema + SPDX/CycloneDX) is
   the public API. It must be standardized, portable, and trustworthy before anything else.
2. **Coverage gates value.** A stamp on 40 % of the fleet yields a blast-radius query with blind
   spots — useless in an incident. knock's value is proportional to it being the *mandatory* path
   for external artifacts. This *was* the riskiest assumption — now **validated** (see below).

## Validated — the core bet holds (2026-06)

A platform / security team has **confirmed they would mandate knock as the single front door** for
external images, so *coverage gates value* is a live requirement rather than a theory. Since then, a
target organization has **proposed** a set of intake requirements; none is committed yet. The ones
that fit the thesis shape *Now*: the small ones are scheduled for implementation, the larger ones go
no further than a design and an ADR. The rest are *Deferred* below or already out of scope.

## What exists

- **Placement.** Copy and rebuild paths driven by one convergent `reconcile`, pluggable hardening
  transforms, a frozen provenance contract (OCI-standard keys + `io.knock.*`, ADR 0020), and
  lifecycle (`purge`, retention). Registry hosts may carry a path prefix, so GHCR, GitLab and
  Artifactory are targetable (#245).
- **Sources.** Git is a source beside registries, and the `skill` artifact class is placed by the
  same convergent `reconcile`: an unchanged revision transfers nothing (ADRs 0048, 0049). An SBOM and
  a scan gate for skills are not built yet.
- **Trust.** Signed attestations on every path when a signer is configured (ADR 0019); an SBOM on
  every placed image, signed under the same identity (ADRs 0029, 0034); `attach` turns upstream scans
  into signed `scan/v1` referrers that record the ruleset a verdict was reached under
  (`ruleset_hash`, ADR 0047), and `gc` collects the superseded ones.
- **Enforcement, after placement.** `attach --fail-on` (ADR 0021); `audit` coverage tiers
  `uncovered < stamped < signed < has-SBOM` with `--fail-on-unsigned` (ADRs 0026, 0036); and
  `knock verify`, the decision verb a promotion gate asks (ADR 0041).
- **Scale.** In-pod concurrency, cross-pod sharding, KEDA-scaled buildkit, and an incremental,
  reconcile-fed scan pipeline driven by `knock scan`, shipped as the optional `knock-oci[scan]` extra
  so that core knock stays redis-free (ADRs 0042, 0043).
- **Adoption surface.** The rename houba → knock, as a clean break (ADR 0045); a published docs site;
  brownfield and greenfield deployment paths (ADR 0044); a
  [migration-from-replication how-to](how-to/migrate-from-replication.md); and a public showcase that
  publishes stamped, SBOM-carrying, keyless-signed images every week
  ([Verify a published stamp](how-to/verify-published-stamp.md), ADR 0046).

CLI verbs: `reconcile · purge · attach · audit · gc · verify · scan · version`.

## Now — admission: the door says no before it places

> Theme: every refusal knock can issue today comes after the bytes are in the registry. `attach
> --fail-on` judges a digest already placed, `verify` judges it at promotion, `audit` reports it after
> the fact. Between the reconcile plan and its application nothing can say no, and nothing records on
> what terms a digest got in. Admission closes both gaps: an evaluation before placement, and a
> signed, write-once record of its outcome. *Admission* here means knock's intake; cluster admission
> (e.g. Kyverno reading knock's facts at deploy time) is unchanged and stays someone else's job.
>
> The small items fit the thesis as it stands and are scheduled for implementation. The larger ones
> change the placement model itself, so they go no further than a design and an ADR until those are
> accepted.

### Small — for implementation

- **Birth verdict — a signed `admission/v1` predicate.** Written once, at placement, and never
  rewritten: the regime the digest was admitted under, the digest evaluated, the rules that failed,
  the `ruleset_hash`, the evaluator and analyzer versions, the vulnerability-database date, and any
  exception granted. It sits beside `scan/v1`, which is re-attested over time and of which `verify`
  keeps the freshest: `scan/v1` says how a digest looks now, `admission/v1` says on what terms it got
  in. Until the gate below exists, the regime says so — never a pass that knock did not evaluate
  (ADR 0020's rule).
- **Required signer.** `KNOCK_ATTEST_SIGNER` defaults to empty, and knock then places without signing
  anything. Add a mode in which knock refuses to place or attest when no signer is configured, so an
  unsigned front door is a configuration error rather than a default.
- **Configurable grace window.** The 7-day digest-stability window is hard-coded (`DEFAULT_GRACE` in
  `domain/reconcile.py`). Once it has passed, knock replaces a tag re-pushed upstream with no verdict
  of any kind — and Docker Hub official images are re-pushed every time their base is refreshed. Make
  the window configurable.
- **Successor on retirement.** A policy field naming the replacement when a policy is retired, so a
  retirement points somewhere instead of just ending. `MirrorPolicy` is `extra="forbid"`, so any new
  field is a schema change.

### Medium — design and ADR only

- **A gate between plan and apply.** Every import, update and rebuild that `reconcile` plans passes an
  external evaluation before it is applied; a refusal drops the operation and leaves what is already
  placed untouched. Two shapes stay open: **(A)** knock calls an evaluator through a port; **(B)** a
  Terraform-style plan/apply seam (`--plan-out` / `--apply-plan`) with the evaluator outside knock,
  which keeps knock free of evaluator-specific code — the line ADR 0039 draws for analyzers. Both
  share one limit: for a rebuild, the bytes worth evaluating are the output, so the gate needs a
  staging area to evaluate them in.
- **Two-phase placement.** Place into a private staging area, then promote: copy the digest, with its
  attestations, to the destination. This is the staging a rebuild gate needs, and it keeps a refused
  digest out of every destination.
- **Sign the image at admission**, not only its attestations. Proposed in ADR 0050 (amends 0041): an
  opt-in `spec.admit` makes `reconcile` sign the placed image after its attestations, and
  `knock verify --require image-signature` reads it. Admission is still a policy-level assertion
  until the gate above lands and the verdict decides each signature.
- **Origin metadata on the copy path.** The upstream inventory and signature are not carried across.
  Stamping changes the digest, so an upstream signature cannot simply travel with the placed image.

### Measure — audit at fleet scale

Nothing yet establishes how `knock audit` behaves on a catalog of hundreds of thousands of
repositories. What exists is a per-image probe benchmark (~1 s/image on a small sample dominated by
fixed costs) extrapolated to 46–115 h for 150k images, over a walk that is still sequential. `--limit`
(#186) makes a sliced run possible: measure the steady-state rate on a real registry, then decide
whether the sequential walk holds or needs concurrency. The same run shows whether `without_sbom` is
ever non-zero, which decides the SBOM gate below.

## Deferred — revisit only on a real signal (YAGNI until then)

These are not refused on principle — they are waiting for a concrete trigger that has not appeared:

- **`audit --fail-on-no-sbom`.** SBOMs are generated on both paths and reconcile backfills kept
  digests (#167), so the gate would guard only pre-unification images and regressions. Add it when a
  fleet-scale audit finds `without_sbom > 0` on a real registry.
- **Readable generated schema reference.** The generated `MirrorPolicy`, `KNOCK_*` and `scan/v1`
  references still render as deep `anyOf > item N` trees. A renderer swap is real tooling work, and it
  serves self-serve onboarding rather than admission. Revisit when a policy author outside the project
  cannot find their way through it.
- **Runnable migration-parity proof.** The how-to ships; a script asserting the SBOM referrer on every
  team copy was drafted and closed unmerged (#180). `knock verify <ref> --require sbom`, run on each
  copy, now performs the same check. Revisit if a migration stakeholder needs to watch it run.
- **Harbor-label selection and registry-webhook triggering.** Both would bind knock to one registry's
  API — Harbor labels are not OCI, and webhook payloads differ per registry — against registry
  independence. They stay in the orchestrator that calls knock until a real signal forces an adapter.
- **More scan formats (CycloneDX, Trivy-native).** No transport gap exists today: Trivy emits SARIF
  and `regis` will. Add a mapper only when a scanner that emits *neither* SARIF shows up.
- **Declaration scaffolding (⑥) — `product_init` / `product_delete`.** CRUD ergonomics around the
  policy declaration. Build only when authoring friction is demonstrably the bottleneck.
- **`MirrorPolicy` as a Kubernetes CRD (visible in ArgoCD).** A CRD with no controller is ceremony;
  a CRD *with* a controller is an operator (see *Runtime presence / fleet inventory*, out of scope).
  Policies already live as YAML in Git, synced and drift-detected, and a `reconcile`/`audit` Job
  surfaces green/red health for free. Revisit only when someone names a decision they would take on a
  per-policy `.status` that they cannot already take from the observability stack.

## Later — directional

- **Developer coverage portal (consumption surface).** A developer-scoped Backstage (TechInsights)
  view that scores per-service provenance coverage off the knock stamp, with vuln posture surfaced via
  an off-the-shelf SBOM/vuln platform (e.g. Dependency-Track). Design is captured (spec + ADR);
  implementation is *Later*, taken only on a real demand signal. Stays true to the thesis — **knock
  stamps, the portal consumes**: it reads the stamp / SBOM referrers, it does not turn knock into a
  query engine or a fleet inventory.

## Explicitly out of scope

- **`proxycache_update` (⑦) — cut (decision closed).** Pure pass-through: no transform, no stamp, so
  it does not fit the stamper essence (*the label is the product*). It belongs in a separate tool, or
  nowhere.
- **Runtime presence / fleet inventory.** knock stamps; it does not watch where its artifacts run. The
  blast-radius query is assembled in the org's observability stack by reading the stamp. Closing that
  loop (native inventory, an operator) is a different, much larger product and is not on this roadmap.
- **Vulnerability store / continuous correlation.** knock emits signed scan *provenance* (the
  `attach` referrer, verified at cluster admission — proof that *this digest came through the front
  door, signed*), not a vuln database. It never re-correlates a frozen package list against today's
  CVE feeds; that *currency* is the org's SBOM/vuln platform's job (e.g. Dependency-Track). The
  referrer is provenance, not a competing store. *(ADR 0032; the reference deployment demonstrates the
  loop with an off-the-shelf Dependency-Track, ADR 0035.)*
- **End-of-life awareness.** Carried by a sibling tool (`regis`).
